# prunecss vs PurgeCSS — 2026-11-26 on `vm`

> **indicative - shared cloud container.** Generated by `bench/run.mjs`. Raw data: the `.json` file with the same name. Every number below can be recomputed from it.

## Headline

- **CLI wall time:** prunecss was 5.4–24.4× faster than the PurgeCSS CLI across 7 corpora (median 9.0×), mean of 10 runs each.
- **Against PurgeCSS's best case** (its JS API in a warmed-up process, no Node startup or file reads) prunecss's *whole CLI run* was 2.3–5.7× faster (median 3.9×).
- **Peak memory:** PurgeCSS used 1.5–8.1× the RSS of prunecss (median of 10 runs per tool).
- **Correctness:** prunecss removed no selector that matches the static DOM of any corpus.

## Correctness: which selectors each tool kept

Selectors are compared as `at-rule context | selector` keys after the shared minifier. "Matches static DOM" means the selector, with pseudo-classes stripped, matches an element when the content files are parsed as HTML (css-select). That is a lower bound on what a page needs: classes added by JavaScript are invisible to it.

Categories used below:

- **at-rule**: Rule without a selector (@keyframes, @font-face, @property, @layer statement, ...)
- **rewritten**: Selector text not present in the input: the tool rewrote it (PurgeCSS trims unused items out of :is() lists; prunecss's printer renames some vendor pseudo-classes). In the false-removal table: the input selector is missing because the tool printed it in a different form
- **escaped**: Escaped class name (Tailwind-style `md\:flex`, `w-1\/2`, `w-\[10px\]`)
- **id**: Contains an #id
- **tag-only**: Only tags / universal / pseudo-classes: no class, id or attribute (e.g. `table`, `h1`, `::selection`)
- **attribute**: Contains an [attribute] selector
- **functional**: Contains :not() / :is() / :where() / :has()
- **pseudo**: Contains a pseudo-class or pseudo-element
- **class**: Plain class selector(s): the tools found different class names in the content
